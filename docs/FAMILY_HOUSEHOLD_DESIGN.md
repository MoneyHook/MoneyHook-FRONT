# 家族の家計記録 — 機能仕様

仕様基準: 2026-09-29。v1の確定要件。DB・API・配備状況は[実装資料](FAMILY_HOUSEHOLD_IMPLEMENTATION_PLAN.md)、設定画面は[UI仕様](FAMILY_SETTINGS_UI_SPEC.md)。

## 所属と対象範囲

- 各自がログインし、有効な所属は同時に1家族、管理者を含め暫定3人まで。
- 作成者が唯一の管理者となり、招待・参加解除・管理者交代を担当する。参加者は過去記録も閲覧でき、退出者はアクセスできない。
- 大カテゴリは共通。支払方法・独自サブカテゴリは個人/家族で分離する。
- v1は家族の手入力・一覧・分析。個人の既存機能は維持する。
- 対象外: 立替・負担割合・精算、複数家族所属、一部メンバーだけへの共有、閲覧専用ロール、個人インポート、通知・チャット、家族予算・定期収支・CSV。未ログイン人物の管理も後段。

## 記録と集計

| 種類                     | 正本・操作権限                                       | 個人/家族の計上                               |
| ------------------------ | ---------------------------------------------------- | --------------------------------------------- |
| 個人・非共有             | 本人の原本。他の家族は閲覧不可                       | 本人だけ1回                                   |
| 本人の家族用（shared）   | 個人原本への共有参照。管理者を含め他の家族は閲覧のみ | 本人と家族に各1回                             |
| 代理/共通財布（proxy）   | 家族が独立所有。参加者全員が編集・削除可能           | 家族だけ1回                                   |
| 退出時の控え（snapshot） | 家族の不変な公開値。参加者が別の訂正/集計除外を保存  | sharedの代わりに家族で1回。本人には原本が残る |

個人集計は原本所有者、家族の人物別集計は支払者ラベルで決まり、両者は一致するとは限らない。代理記録の支払者指定・変更でも個人データは作成/更新しない。本人の4,800円を共有すれば本人と家族に各4,800円、代理なら家族だけ。個人と家族の合計を足して総支出にしない。

個人一覧は所有する全原本を表示し、家族切り替え・共有フィルタ・共有バッジを追加しない。共有状態の確認・開始・解除は家族の共有管理画面へまとめる。

収入も同じ構造（支払者を受取者とする）。整数円・`YYYY-MM-DD`・string IDを使い、カード購入/引落を二重計上せず家族間送金を収支にしない。収支差額は口座残高ではない。個人予算は本人原本が対象。

## 入力と画面

個人のホーム・取引・分析・設定を維持し、ホームから家族へ、設定から家族設定へ進む。家族は専用routeを使い、Sidebar/スマホナビには家族のホームだけを置く。詳細routeは[router](../src/app/router/router.tsx)。

- `/app/family`: 月次収支・最近の記録。`transactions`・`analysis`・`sharing`は一覧・分析・保存済み原本の共有管理。
- `/app/family/new`: 家族側から追加（入力先選択を維持）。`transactions/:transactionId/edit`: 本人の共有原本編集。
- `/app/settings/family`: 所属・メンバー・招待・入力先。`/app/family/join`: 招待参加。

家族・月・一覧条件はURLに保持し、旧個人URLの`scope=household`は家族へ誘導する。キャンセル/編集後は遷移元、新規保存後は保存先の月へ進む。個人編集に共有パネルを置かず、共有原本の更新/削除時だけ家族への影響を確認する。家族API失敗で個人保存を止めない。

- 新規入力は個人/家族を選び、家族では本人/代理を区別する。本人は「自分の記録にも保存」、代理は「家族のみ・支払者の個人記録には反映されない」と案内する。
- 既定入力先はユーザー設定APIで端末間同期、未設定は個人。明示リンク・家族画面の追加を優先し、再取得で入力中の登録先を変えない。1件の選択変更では既定値を更新しない。
- 個人↔本人共有で日付・金額・名称・分類・支払方法を保持する。本人↔代理では参照が異なるため分類/支払方法を選び直す。送信中は変更不可、開始時の種類・家族へ保存する。
- 未参加は個人のみ。退出/解除後の新規は個人を初期値にして理由を表示する。入力中の家族データを無断で個人保存しない。編集は既存種類を保ち、新規の既定値を適用しない。
- 家族一覧で出所と支払者、詳細で登録者・最終更新者を確認できるようにする。

## 共有・参照情報・重複

- 原本の支払者/所有者は本人固定。共有の編集・削除・解除は家族側分類/支払方法も含め本人だけ。APIでも管理者を例外にしない。
- 原本編集は共有にも反映。削除は両方から外れることを確認し、論理削除と共有終了を一括で行う。退出後の控えは変更しない。
- 個人→家族は共有開始、逆は共有解除。解除は原本を保持し、家族集計から外れると示す。通常解除で控えは作らない。
- 本人の登録/共有では個人の分類・支払方法を1回だけ選び、名前・支払条件から家族項目を自動作成/再利用する。家族選択欄は増やさず、共有・自動追加を案内する。
- 照合はサブカテゴリの親カテゴリ/名前、支払方法の名前/種別/締め日/支払日。未設定・0の締め日は既存仕様どおり31日。有効な一致が複数あれば最も古いIDを使い、無効項目は復活させない。
- 項目解決と保存は家族ロック下の同一DB transaction。原本の選択変更は変更項目だけ家族へ反映し、支払方法解除も反映する。個人設定の名称/条件変更、既存データ一括補完、金額のみの編集で家族分類を書き換えない。
- 使用済み家族項目は無効化して候補から外し、既存参照/表示を保持する。他人の共有記録を設定変更から間接的に書き換えない。
- 代理の支払者は参加メンバーまたは家族共通。控えの訂正は最新内容だけ別保存し、原本へ伝播しない。

代理と本人共有は二重計上され得る。日付・金額・支払者の一致を候補表示し、自動統合しない。v1では本人が個人の非共有原本を手入力するか、共有後に代理を確認して手動削除する（削除まで重複）。インポート用の空UI/APIは作らない。

v2案: 支払者本人だけが新規/既存原本を選んでインポートし、同じ代理entry IDを共有参照へ切り替える。以後は本人だけ編集可能。自動原本作成を避け、差分確認・既共有との統合・同時操作/再送の冪等性・家族件数/合計維持を設計する。v1の実装/検証対象には含めない。

## 退出・解除・再参加

退出と管理者による参加解除は同じ処理。本人の有効sharedを、家族公開項目だけのsnapshotへ同一ID・支払者のまま切り替え、同期/原本読み取り権限を切って所属を終了する。本人は原本を保持し、家族の控えを閲覧できない。代理記録は登録者の退出後も家族に残し、個人設定は控えへコピーしない。

同時編集と退出をAPIで直列化し、version確認・控え確定・所属終了を単一transactionで行う。失敗/再試行でも権限や重複控えを残さず、本人/家族の月次合計を維持する。

再参加で控えを原本に自動接続しない。明示切り替えは将来機能とし、v1では控えに対応する原本の再共有を拒否する。

管理者は参加済みメンバーへ交代してから退出する。最後の1人は家族をarchiveし、sharedを控えに変えて同期を切り、招待/入力/更新を停止する。終了時のarchivedメンバーだけ閲覧でき、既にleftの人へ権限を与えない。archiveの閲覧枠は有効所属枠と分け、新しい家族への参加を妨げない。

アカウント退会は別仕様。提供前に控えの氏名・保存期間・匿名化/完全削除を定める。

## 招待

管理者がコード/同じ招待を開くリンクをコピーしてLINE等で渡す。アプリから自動送信しない。受取人はログイン後に家族名・招待者・過去分閲覧/共有原本は閲覧のみ/代理は共同編集を確認して承諾する。追加承認は不要。

- 暗号学的乱数による紛らわしくない英数字10文字、5文字区切り。入力時は大小文字・区切りを正規化。期限は24時間、1人1回。
- 有効招待は空き枠数まで（管理者だけなら最大2）。取消・再発行で旧コード/リンクを失効させる。
- リンクはコードから導出しない十分長い別token。同じ招待ID/状態を使い、どちらで承諾しても両方使用済みにする。GET/プレビューで消費しない。
- 照合は認証後。照合前は家族情報を公開せず、承諾前も必要最小限だけ表示する。未認証はログイン後に安全な参加画面へ戻す。第三者への転送でも参加可能な方式と発行者へ説明する。
- 平文のコード/tokenは保存せず照合値を保持し、衝突を防ぐ。アカウント/送信元の試行制限、ログ/分析/外部送信への秘密混入防止を行う。
- 承諾時に期限・未使用・未取消・家族active・発行者管理権限・参加者所属・最大3人を再確認し、所属追加/消費を一括処理する。自己招待・他家族所属・二重参加を拒否し、失敗/再送で枠や招待を消費しない。
- 状態は有効/使用済み/期限切れ/取消。未承諾はメンバー数に数えない。管理者交代/archiveで旧管理者の未使用招待を失効。満員/無効時は案内を表示する。

## API・フロントエンドの境界

所有者・登録者・更新者はAPIが認証と操作から決め、自由なowner/種類変更を許さない。共有開始/解除/退出は専用操作で権限・version・参照を確認する。家族側の編集権限は個人原本への権限にならず、読み取り/変更/集計の全経路で検証する。

sharedの金額は原本が正本、proxy/snapshotは家族の独立値。一覧・詳細・各集計で同じ定義を使う。競合時は入力を保持して再取得を案内し、作成/承諾/退出は冪等にする。既存個人記録を自動公開しない。

OpenAPIから生成し、pageでfeatureを合成する。入力先と閲覧条件を分け、query/cacheをユーザーと家族で分離する。家族取引/分析は永続化せず、設定参照の限定キャッシュは[状態方針](ARCHITECTURE.md#状態の所有者)に従う。権限喪失時の遅延結果/再表示を防ぎ、退出で家族cacheを破棄して個人原本を再取得する。

共有更新では個人/家族の関係月を無効化。別端末更新はフォーカス復帰・画面表示・手動更新で取得し、v1はリアルタイム通信なし。

契約の検証対象と導入手順は[実装資料](FAMILY_HOUSEHOLD_IMPLEMENTATION_PLAN.md)に集約する。
