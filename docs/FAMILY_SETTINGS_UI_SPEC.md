# 家族設定画面 UI 仕様

更新日: 2026-09-30

この資料は `/app/settings/family` の画面設計と実装判断をまとめる。家族機能全体の業務仕様は [FAMILY_HOUSEHOLD_DESIGN.md](FAMILY_HOUSEHOLD_DESIGN.md) を正本とし、この資料では設定画面に必要な情報と優先順位だけを扱う。

実装前に作成した完成イメージは [family-settings-concept.png](assets/family-settings-concept.png) を参照する。人物写真や架空のメールアドレスは構成検討用であり、実装対象には含めない。

## 1. 画面の目的

家族設定は、現在参加している家族の状態を短時間で把握し、日常的な設定と管理操作を迷わず行うための画面とする。

- 家族名、状態、自分の権限、参加人数を確認する
- 自分の表示名と、新規入力の既定の登録先を変更する
- メンバーを確認し、管理者は招待・管理者交代・参加解除を行う
- 家族専用の支払い方法とサブカテゴリを管理する
- 家族未参加時は、家族の新規作成または招待からの参加を行う
- 終了済みの家族は閲覧専用であることを理解したうえで記録へ移動する

家計記録の閲覧・入力・分析は家族画面で行い、設定画面に集計情報や取引一覧を重複させない。

## 2. 必要な情報と操作

| 領域           | 表示する情報                         | 主な操作                                     | 権限・条件                                     |
| -------------- | ------------------------------------ | -------------------------------------------- | ---------------------------------------------- |
| 家族の概要     | 家族名、状態、参加人数、自分の権限   | 表示対象の家族を切り替える、家族の記録へ移動 | 参加中・終了済みの家族                         |
| 自分の設定     | 家族内の表示名、新規入力の既定値     | 表示名を保存、個人用・家族用を選択           | 有効な家族の全メンバー                         |
| メンバー       | 表示名、管理者、退出済み             | 管理者交代、参加解除、退出、家族終了         | 管理操作は管理者のみ。管理者は交代前に退出不可 |
| 招待           | 有効期限、状態、発行済みコード       | 発行、リンクのコピー、再発行、取消           | 有効な家族の管理者のみ。最大3人                |
| 家族専用マスタ | 支払い方法、サブカテゴリ、有効・無効 | 追加、編集、有効化・無効化                   | 有効な家族の全メンバー                         |
| 未参加時       | 作成条件、招待コード                 | 家族を作成、招待を確認して参加               | 有効な家族に未参加の場合のみ                   |

## 3. 情報設計

有効な家族では、上から次の順に並べる。

1. 概要バー: 表示中の家族、状態、人数、家族の記録への導線
2. 日常設定: 自分の表示名、新規入力の既定値
3. メンバー: 一覧と権限に応じた管理操作
4. 招待: 管理者だけに表示し、発行結果と招待履歴を同じ領域に置く
5. 家族専用マスタ: 支払い方法とサブカテゴリをタブで切り替え、一覧を確認しながら追加・編集する
6. 危険な操作: 退出または家族終了を末尾に分離する

未参加時は「家族を作成」と「招待から参加」を同格の選択肢として提示する。終了済み家族では編集領域を隠し、閲覧専用の状態と家族記録への導線を優先する。

## 4. 表示状態

- 読み込み中: ページ構造を保つ簡潔な読み込み表示を出し、操作を表示しない。
- 読み込み失敗: 画面上部にエラーを表示する。既に取得済みの内容があれば消さない。
- URLで指定した家族にアクセス不可: 理由と設定入口への戻り先を表示する。
- 有効な家族: 編集可能な領域を表示する。
- 終了済み家族: 「終了・閲覧専用」を明示し、家族の記録への導線だけを残す。
- 招待発行直後: コードを最も強く表示し、期限、コピー操作、共有上の注意を続ける。
- 保存中: 対象操作を無効にし、二重送信を防ぐ。

## 5. ビジュアル方針

### Visual thesis

家族概要・自分の設定・メンバー・招待・家族専用設定をカード単位にまとめる。背景と異なるカード面、境界線、統一した内側余白でまとまりを明確にし、入力欄には背景色を、選択中の入力先にはアクセント色を付ける。退出・終了操作は専用カードと控えめな警告色の境界線で区別する。

### Content plan

- Overview: 家族名、状態、人数、記録への導線
- Everyday settings: 自分に関する2つの設定
- People and invitation: メンバーと招待の管理
- Family references: 家族専用の支払い方法・サブカテゴリ
- Destructive actions: 退出・家族終了

### Interaction thesis

- セクションは短いフェードと移動で順番に現れ、情報の読み順を補助する。
- 個人用・家族用の既定値は、選択結果がその場で分かる2択コントロールにする。
- 招待コードの発行結果とマスタ編集フォームは、同じ場所で展開して文脈を維持する。

## 6. レスポンシブ方針

- モバイルは1列で、主要操作を幅いっぱいにし、行内操作は必要に応じて折り返す。
- デスクトップは本文幅を広げすぎず、概要と日常設定、マスタのフォームと一覧に限って2列を使う。
- メンバー名と状態を先に読み、操作は右側または次の行に置く。
- 画面下部のモバイルナビゲーションと重ならない余白を確保する。

## 7. アクセシビリティと文言

- 状態は色だけで表さず、「管理者」「退出済み」「終了・閲覧専用」などの文言を併記する。
- 破壊的操作には結果を含む確認文を表示する。
- アイコンは補助用途に限定し、操作名はテキストで表示する。
- 入力には常にラベルを関連付け、エラーは `role="alert"`、読み込みは `role="status"` を使う。
- タップ対象はモバイルで十分な高さを確保する。

## 8. 実装の受け入れ条件

- 既存APIの操作と権限制御を変更しない。
- 有効・終了済み・未参加・アクセス不可・読み込み失敗の各状態が判別できる。
- 管理者以外に招待、管理者交代、参加解除を表示しない。
- 自分の表示名、新規入力の既定値、招待、家族専用マスタの既存操作を維持する。
- light/dark themeでsemantic color tokenを使い、色だけに依存しない。
- 320px幅からデスクトップまで横スクロールせず操作できる。
